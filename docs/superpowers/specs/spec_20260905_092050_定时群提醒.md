# QQ 机器人定时群提醒设计

## 1. 目标

为现有 NapCatQQ + OneBot 11 + Python + Qwen 机器人增加定时群提醒能力：

- 每天北京时间 09:00 向配置群发送早间提醒；早间提醒由 Qwen 生成，包含当天日期和星期，暂不接入天气 API。
- 每天北京时间 21:00 向配置群发送早点休息提醒；内容由 Qwen 生成。
- 每天北京时间 11:00、13:00、15:00、17:00、19:00 向配置群发送喝水提醒；内容使用固定配置文本，不调用 Qwen。
- 所有定时消息只发送到配置的群号，不按群名匹配。
- 机器人启动晚于某个任务时间时不补发已错过的提醒。
- 不修改 NapCat 配置、`launcher.bat` 或 OneBot WebSocket 方向。

## 2. 配置

在项目根目录 `.env` 和 `.env.example` 中增加以下配置：

```dotenv
REMINDER_ENABLED=true
REMINDER_GROUP_IDS=1036995638
REMINDER_TIMEZONE=Asia/Shanghai
REMINDER_MORNING_TIME=09:00
REMINDER_NIGHT_TIME=21:00
REMINDER_WATER_TIMES=11:00,13:00,15:00,17:00,19:00
REMINDER_WATER_MESSAGE=现在是喝水时间，记得补充水分哦～
```

配置规则：

- `REMINDER_ENABLED=false` 时不启动定时提醒线程。
- `REMINDER_GROUP_IDS` 使用逗号分隔群号；空值表示没有发送目标，程序记录警告但不发送。
- `REMINDER_TIMEZONE` 默认 `Asia/Shanghai`，所有任务按该时区判断。
- 时间字段使用 `HH:MM` 格式。
- `REMINDER_WATER_TIMES` 使用逗号分隔多个 `HH:MM` 时间。
- `.env.example` 只能使用示例群号和示例文本，不得包含真实 API Key 或真实私密配置。

## 3. 架构

新增两个职责明确的模块：

```text
bot/
├─ scheduler.py          # 定时循环、时区转换、任务去重
└─ reminder_service.py   # 三类提醒内容生成和群发送
```

现有模块调整：

- `bot/config.py`：将提醒配置解析为类型明确的 `Settings` 字段。
- `bot/onebot_client.py`：提供可被提醒服务调用的 `send_group_message`，不承担时间判断。
- `bot/__main__.py`：加载配置，按开关创建并启动调度线程，再运行 WebSocket。
- `bot/qwen_client.py`：继续负责 Qwen 调用，不增加调度逻辑。

数据流：

```text
bot.__main__
  ├─ load_settings()
  ├─ QwenClient(settings)
  ├─ NapCatBot(settings, qwen_client)
  ├─ ReminderService(settings, qwen_client, bot.send_group_message)
  ├─ ReminderScheduler(...).start()
  └─ NapCatBot.run()
```

调度器与 WebSocket 使用不同线程：

- 主线程持续运行 OneBot WebSocket；
- 后台线程按 `Asia/Shanghai` 检查任务；
- 调度器调用提醒服务生成内容，并对每个配置群调用 `send_group_msg`。

## 4. 提醒内容

### 4.1 早间提醒

09:00 任务调用 Qwen，用户提示至少包含：

```text
今天是 YYYY 年 M 月 D 日，星期X。
天气信息暂未配置。
请生成一段简短、自然、适合发送到 QQ 群的早安提醒。
```

日期由目标时区的当前日期生成，不从系统默认时区猜测。Qwen 失败时使用固定兜底文本，仍继续向配置群发送。

### 4.2 喝水提醒

喝水任务不调用 Qwen，直接使用 `REMINDER_WATER_MESSAGE`。默认文本为：

```text
现在是喝水时间，记得补充水分哦～
```

### 4.3 晚间提醒

21:00 任务调用 Qwen，用户提示至少包含：

```text
现在是晚上 9 点。
请生成一段简短、自然、提醒 QQ 群成员早点休息的话。
```

Qwen 失败时使用固定兜底文本，仍继续向配置群发送。

## 5. 调度规则

调度器维护当天已执行任务集合，任务键格式为：

```text
YYYY-MM-DD:morning
YYYY-MM-DD:water-HH:MM
YYYY-MM-DD:night
```

每次检查：

1. 获取 `REMINDER_TIMEZONE` 对应时区的当前时间。
2. 查找当前 `HH:MM` 命中的任务。
3. 对当天尚未执行的任务执行一次。
4. 先标记任务，再执行发送，避免同一分钟内重复触发。
5. 进入下一次检查。

采用“当前分钟匹配”而非“寻找最近过去任务”的策略，因此启动后不会补发错过的任务。例如 10:00 启动不会补发 09:00 早间提醒。

调度循环使用可配置的短暂检查间隔（实现默认约 1 秒），并支持停止事件，避免固定长睡眠导致停止不及时。调度线程异常必须记录日志，不得静默退出；发送某一个群失败时继续尝试其余群。

## 6. 群发送范围

提醒服务只遍历 `REMINDER_GROUP_IDS` 解析出的群号：

```python
for group_id in settings.reminder_group_ids:
    send_group_message(group_id, content)
```

不查询群名，不根据群名模糊匹配，也不向事件来源之外的其他群发送。群号在配置加载时校验为正整数列表；非法值应给出清晰配置错误，而不是运行到发送阶段才失败。

## 7. 错误处理

- 缺少 `DASHSCOPE_API_KEY`：沿用现有入口行为，启动前退出并提示配置位置。
- `REMINDER_GROUP_IDS` 为空：调度器可启动但每项任务不发送，并记录警告；推荐启动时直接提示没有提醒目标。
- 时间格式非法：配置加载阶段抛出带字段名称的 `ValueError`。
- Qwen 早间/晚间调用失败：记录异常，使用各自固定兜底内容。
- 某群 `send_group_msg` 失败：记录群号和错误，继续发送其他配置群。
- WebSocket 断开：沿用现有 OneBot 客户端行为；调度器线程不应因此崩溃。
- 进程重启：不恢复执行集合，不补发之前任务；只处理重启后新到达的时间点。

## 8. 测试设计

不等待真实时间，不调用真实 Qwen API，不连接真实 NapCat。通过注入时钟、假的 Qwen 客户端和假的发送函数测试：

### 配置测试

- 正确解析逗号分隔群号；
- 正确解析提醒时间和时区；
- 正确解析开关；
- 非法群号和非法时间给出明确错误；
- 环境变量优先于 `.env`。

### 提醒服务测试

- 早间调用 Qwen，并传入日期、星期和天气未配置说明；
- 晚间调用 Qwen；
- 喝水使用固定文本且不调用 Qwen；
- Qwen 失败时使用对应兜底文本；
- 多个群逐个发送，单群失败不阻断其他群。

### 调度器测试

- 09:00 触发早间任务；
- 五个喝水时间分别触发一次；
- 21:00 触发晚间任务；
- 非任务时间不触发；
- 同一分钟重复检查不会重复发送；
- 10:00 启动不补发 09:00；
- 使用 `Asia/Shanghai` 的时间判断；
- 停止事件能结束调度循环。

### OneBot 集成测试

- 定时提醒使用 `send_group_msg` 和配置群号；
- 原有私聊 Qwen 回复不变；
- 原有群聊仅 @机器人回复不变；
- 机器人自身消息仍被忽略。
